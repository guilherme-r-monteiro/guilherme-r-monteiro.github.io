vision-agent-mcp

26/36 → 28/36

MCPPythonONNX Runtimeevaluation

An LLM agent needs computer-vision tools, and the quality of the tool descriptions decides how well it uses them.

Build, result and limits
What was built
An MCP server with five tools (list, detect, count, summarize and compare images) over a YOLOv8n ONNX detector, and a 36-case harness that scores the agent against COCO128 labels. Typed Python with 14 unit tests.
Measured result
The agent scored 26/36 with the tools as first written. One sentence in two tool descriptions (retry once at lower confidence) lifted it to 28/36. The detector alone scored 26/36.
Limits
36 cases and one run per setting, so the gain is a signal and not proof. The detector was trained on COCO images, so absolute numbers are optimistic. The README lists two evaluation flaws found and fixed.

cv-label-audit

89% of injected label errors found

data qualityYOLOv8SQLiteevaluation

Built for: Computer vision engineering roles

Detection datasets carry label errors, and reviewing every image is slow.

Build, result and limits
What was built
A detector-based audit that flags missing boxes, wrong classes, loose boxes and unsupported boxes, stores findings in SQLite, and ranks images for review with one SQL query. Scored against errors injected with a fixed seed.
Measured result
Recall 0.89 on auditable injected errors at the lowest threshold, precision 0.23. The top 10 review queue holds an injected error in 72% of images against 31% at random.
Limits
COCO128 only. The detector saw these images in training, so recall is optimistic. Deleted boxes are found only 30% of the time. The audit was revised once after a first run raised too many flags.
Link
Repository: public after review

cv-training-lab

90.4% test accuracy

PyTorchCIFAR-10model registryGrad-CAM

Built for: Computer vision engineering roles

A training workflow needs architecture choice, tuning, versioning, explanation and monitoring, not only a model.

Build, result and limits
What was built
A reproducible CIFAR-10 pipeline: three architectures, random hyperparameter search, a file registry with checksums and promotion rules, Grad-CAM with a deletion test, and a drift monitor.
Measured result
Test accuracy 0.706 (small CNN), 0.837 (ResNet-18 scratch), 0.904 (ResNet-18 pretrained). Search lifted the small CNN from 0.656 to 0.694. The drift monitor had no false alarms and flagged all four corruptions at 0.96 or above.
Limits
One seed per row, 20,000 training images, one GPU. The Grad-CAM check is informative for the scratch model and not for the pretrained one. A first deletion test used an unfair baseline and was replaced.

edge-inference-bench

266 tok/s GPU, 78 CPU

C++llama.cppCUDAbenchmark

Built for: Inference engineering roles

Running a language model locally needs known load time, memory and speed under real settings.

Build, result and limits
What was built
A C++17 harness over llama.cpp that measures load time, resident memory, prefill and decode speed, thread scaling, quantisation, load mode and long-session behaviour, on CPU and CUDA builds.
Measured result
Decode speed stops scaling at 4 threads. Q8_0 decodes 12 to 15% slower than Q4_K_M. On the CPU, decode speed halves between 500 and 3,500 tokens of context. On the GPU it falls 7%.
Limits
One 0.5 B model, one machine, warm page cache. No changes to llama.cpp itself and no Vulkan or Metal build.
